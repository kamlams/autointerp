How detection is scored

Detection asks whether the explanation can predict where the feature fires, with no hints. The examiner sees the explanation and 40 snippets it has never seen during explanation, each with one probe token marked [[ ]], and answers 0 or 1 per snippet. The answer sheet is the activation record itself.

firing probes (20)
positions where the feature actually fired, drawn from the held-out pool and stratified over activation — half by rank bins (equal population), half by activation-value bins (equal width), so heavy-tailed features have their strong regime probed too.
non-firing probes (20)
uniformly random corpus positions where the feature did not fire (checked against the full firing index).
what the examiner sees
up to 31 tokens of left context, the probe token wrapped in [[ ]], 8 tokens of right context shown for readability only (activations are causal), the probe token repeated in the header with its sequence position, and [START] when the window begins at position 0.
question
"Does the feature fire on the probe token, per the explanation?" — 5 snippets per call, reply as a JSON array of 0/1.
score
balanced accuracy = (TPR + TNR) / 2, chance 0.50; unparseable or failed batches are excluded and counted. tpr_by_strength reports the hit rate per activation decile, which is how the weak-regime misses above were diagnosed.

The exact prompt (system message)

You will evaluate a proposed explanation of a language-model feature against text snippets.

Explanation of the feature:
{explanation}

You will see 5 snippets. In each snippet exactly one token is wrapped in [[ ]] — the probe token; the header repeats it and gives its position in the sequence. A snippet beginning with [START] starts at the first token of its sequence. The feature reads only the probe token and the text BEFORE it (the text after it is shown for readability only). For each snippet, decide whether this feature fires ON THE PROBE TOKEN. Answer 1 if, per the explanation, the feature fires on the [[probe token]]; answer 0 if it does not. Ignore other occurrences of similar tokens elsewhere in the snippet.

Reply with ONLY a JSON array of 5 integers (0 or 1), e.g. [1,0,0,1,1]. No other text.

Why the probe is marked rather than placed last: an earlier version cut each snippet at the probed token and asked about "the final token". Weak examiners then judged whichever similar token they noticed anywhere in the text — a "to" explanation was scored against a "to" three words earlier. Marking the probe removed that failure without changing what is measured.

How fuzzing is scored

Fuzzing asks whether the explanation is precise enough to verify a location. The examiner sees snippets in which exactly one token is marked << >>; in half of them the mark sits on a real strong firing, in the other half it was deliberately moved to a token where the feature does not fire. Correct and wrong probes come from the same kind of text, so an explanation that only names a topic cannot tell them apart.

pairs (20)
anchors are strong firings only (≥ 30% of the feature's maximum activation), stratified over rank and value bins; each bin yields one correct snippet and one wrongly-marked twin, so the two classes have identical strength distributions.
correct probe
the anchor token wrapped in << >>. Nothing else is marked, even where the feature also fires.
wrong probe
a snippet from the same bin whose mark is moved to a random token with zero activation inside the same window.
one mark per probe
every probe is a single judgment. Multi-mark probes (up to five marks) made the task ill-posed whenever the marks carried mixed evidence — e.g. Flick<<ering>> next to batch<< renders>> under a verb-based explanation — and reasoning examiners expanded every reading for up to 98k tokens without answering. With one mark the same batches finish in seconds.
question
"Does the explanation predict that the feature fires on the marked token?" — 5 snippets per call, JSON array reply.
score
balanced accuracy over 20 correct + 20 wrong probes. TPR = correct marks accepted (coverage of the strong regime); TNR = wrong marks rejected (precision).

The exact prompt (system message)

You will evaluate a proposed explanation of a language-model feature against text snippets with marked tokens.

Explanation of the feature:
{explanation}

You will see 5 snippets, each with EXACTLY ONE token wrapped in << >> marks; a snippet beginning with [START] starts at the first token of its sequence. In some snippets the mark is on a token where this feature fires strongly; in others it is on a wrong token where the feature does not fire at all. No other token is ever marked, even if the feature also fires elsewhere in the snippet — judge only the marked token. For each snippet, answer 1 if the explanation predicts that the feature fires on the marked token, and 0 if it does not.

Reply with ONLY a JSON array of 5 integers (0 or 1), e.g. [1,0,0,1,1]. No other text.

Reading detection and fuzzing together. Detection rewards coverage: it samples the whole activation range, so an explanation that describes only the strong regime loses TPR on weak probes. Fuzzing rewards precision on the strong regime: its correct and wrong probes share the same text, so a vague explanation scores at chance. A trustworthy explanation needs both.

Sampling principles

What the explainer is shown decides what it can find. Every rule below was added after a specific failure on these five features; each is deterministic (per-feature seed, temperature 0) so runs are reproducible and comparable.

1. A statistics card comes first

Sampling throws away the sufficient statistics of a feature; the card restores them at no LLM cost. For every feature it lists density, firing rate and mean activation by sequence position, and the most common fired-on and preceding tokens — among the 2,000 strongest firings and among all firings — each with its conditional rate: how often any occurrence of that token in the corpus fires, or is followed by a firing. Shares say what is common among firings; conditional rates say how reliably a token triggers the feature. This is what separates feature 25337's mechanism (" cut" is followed by a firing 100% of the time) from its symptoms (" up" is the most common fired-on token but fires on only 21% of its occurrences).

2. Twenty-four snippets, chosen against three failure modes

Not only the top. The strongest firings tell a cleaner story than the feature does — feature 12298 looks perfectly "after a" at the top and messy below. 8 of the 24 snippets come from the 200 strongest firings; the other 16 are stratified over the whole activation range, half by rank bins and half by activation-value bins, so heavy-tailed features (14825: median 0.36, maximum 4.58) still show their strong regime.

Not one story. Diversity quotas are proportional to each key's share of the candidate pool (compressed by ½, floor of 2, overflow when a key runs out) on three keys: the (preceding, fired-on) bigram, the preceding token alone, and the fired-on token alone. Before quotas, 7 of feature 25337's top 8 snippets were cut/kick. At most 4 snippets may come from one sequence.

Not without position. Feature 14825 fires twice as often at position 0. Windows that start at the first token carry a [START] marker, every snippet header gives the anchor's position and its strength on a 0–10 scale, and the card has a position profile.

Marks by class. Every firing in a window is marked, but by its true class: <<strong>> at ≥ 30% of the feature's maximum, <weak> below — so the explainer can see that " pass" at 0.2 of maximum next to " to" at 0.9 is spillover, not a second pattern. Marks are per token, never merged: "a<< lot>><< of>>" is two firing tokens, not one firing phrase.

--- Snippet 3 (strength 6/10, anchor at position 41) ---
Marriage is an explaining factor of per capita GDP. This is an example of a left-handed< proof>< using> Traditional Marriage. A left-handed< proof> constitutes half<< of>>< the> CAE Interpretive Proof. While
(feature 25337 explainer snippet: one strong firing, four weak spillovers)

3. Dense features get a different treatment

At ≥ 10% density (14825 and 24792 here) "where it fires" is not the question. Strong marks additionally require the 75th percentile of the feature's activations, the explainer is told the density outright, and it is shown six contrast snippets in which the probe token does not fire — because for a 93% feature the informative tokens are the silent ones.

4. Held-out, disjoint, deterministic

  • The explainer's 24 snippets, the 40 detection probes and the 40 fuzzing probes never share a position; a probe the explainer has seen would let the explanation "quote the test".
  • Every random choice comes from seed × 100003 + feature_id; the sampler produced identical probe sets for all three runs, so the models are compared on the same questions.
  • Context is 31 tokens left and 8 right of the anchor; byte fragments of split multi-byte characters are merged so a mark never lands on half a character.

Reading the cost. The reasoning DeepSeek model is the working default: correct explanations in eight minutes for five features. Retries are classed by cause. Kimi's first pass lost feature 14825 when the gateway dropped seven of eight parallel streams at once. Since then a call that exhausts its thinking budget is retried with the budget doubled (up to 128k); a gateway or network failure is retried at the same budget up to 30 times; only a model that finishes without producing text is not retried. A batch that still fails is excluded and counted, never voiding the feature, and Kimi runs with 3 concurrent calls. The 14825 rerun under this policy saw three budget-doubling retries, all recovered, and no drops.
